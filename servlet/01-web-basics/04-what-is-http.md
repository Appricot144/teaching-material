# HTTP とは何か

> 疑問: HTTP とは何か。
>
> 答え: クライアントと Web サーバがやり取りするときの通信の決まりです。クライアントがリクエストを送り、サーバがレスポンスを返します。

## リクエスト

`GET /myapp/hello?name=taro` というリクエストは、次のような形式です。

```http
GET /myapp/hello?name=taro HTTP/1.1
Host: example.com
User-Agent: Mozilla/5.0
```

| 部分 | 内容 |
|---|---|
| リクエスト行 | HTTP メソッド、パスとクエリ、HTTP のバージョン |
| ヘッダー | 接続先や送信元ソフトウェアなどの追加情報 |
| ボディ | サーバへ送るデータ（省略できる） |

## レスポンス

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<!DOCTYPE html>
<html>...</html>
```

| 部分 | 内容 |
|---|---|
| ステータス行 | HTTP のバージョンと結果を表すステータスコード |
| ヘッダー | 本文の形式などの追加情報 |
| ボディ | 返す内容 |

ヘッダーとボディの間には空行が入ります。ブラウザは `Content-Type` を見て、ボディをどう扱うか判断します。

上の形式は HTTP/1.1 のものです。HTTP/2 以降は通信上の表現が異なりますが、メソッドやヘッダーなどの考え方は同じです。

## 主な HTTP メソッド

| メソッド | 用途 |
|---|---|
| `GET` | リソースを取得する |
| `POST` | サーバへデータを送り、処理してもらう |
| `PUT` | リソースを置き換える |
| `DELETE` | リソースを削除する |

## 主なステータスコード

| コード | 意味 | 例 |
|---|---|---|
| 2xx | 成功 | `200 OK` |
| 3xx | リダイレクト | `302 Found` |
| 4xx | クライアント側の問題 | `404 Not Found`、`405 Method Not Allowed` |
| 5xx | サーバ側の問題 | `500 Internal Server Error` |

## ステートレス

HTTP はステートレスです。つまり、プロトコル自体は前のリクエストの内容を覚えていません。ログイン状態などを保つには、Cookie やセッションといった別の仕組みを組み合わせます。
