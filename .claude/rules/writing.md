# 教材の執筆ルール（共通）

このリポジトリの教材（`servlet/` や `spring/` などのドキュメントディレクトリ）を書く・直すときに、全ドキュメントで共通して従うルール。

Markdown の構成・装飾・列挙・表の書き方は、`~/.claude/rules/markdown-documentation.md` に従う。

## ドキュメントごとのルール

想定する読者など、ドキュメントごとに異なるルールは、各ドキュメントディレクトリの `.claude/rules/` に置く。

- 例: `servlet/` の教材のルールは `servlet/.claude/rules/` に置く
- 教材を書く・直す前に、そのドキュメントディレクトリの `.claude/rules/` を読む
- 共通ルールとドキュメントごとのルールが食い違うときは、ドキュメントごとのルールに従う

## 想定する読者の扱い

ドキュメントごとのルールで定めた読者が知らないことを、前提知識として使わない。使う場合は、その場で説明するか、説明しているファイルへリンクする。

## 説明の進め方

- 基本的な概念を説明するときは、読者が抱きそうなシンプルな疑問から始める
- 読者が知っている簡単な概念を組み合わせて、新しい概念の理解を作る
- 正確さよりもシンプルさを優先する。細かい例外や厳密な定義は本文に入れない

## 参考文献

章（`01-web-basics` などのディレクトリ）ごとに、正確な概念を知るための資料や次のステップとなる資料を紹介する。

- 紹介は、章の最後のファイルの末尾に、その章全体の分をまとめて書く
- 補遺（`appendix-*.md`）は、章の最後のファイルとして扱わない
- 紹介する資料は、公式ドキュメントと、推奨される書籍や記事とする

本文で単純化した内容は、ここで紹介する資料で正確に学べるようにする。
