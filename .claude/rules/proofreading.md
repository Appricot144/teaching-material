# 教材の校正の進め方

このリポジトリの教材を見直す（校正する）ときに従う進め方。

## 1ページずつ直す

校正は1ページ（1ファイル）ずつ行う。

細かい表現の修正を、すべてのページへまとめて反映しない。まとめて反映すると、利用者がすべてのページを見直さなければならなくなる。他のページに同じ問題があっても、そのページの番が来るまで直さない。

## 手順

1. ページを開く
2. 執筆メモと執筆ルールを確認する
3. 執筆メモと執筆ルールに照らした変更を、提案として示す
4. 利用者が気になった部分を、話し合いながら直す

## 確認するもの

- 執筆ルール: リポジトリのルートの `.claude/rules/writing.md` と、ドキュメントディレクトリの `.claude/rules/`（`servlet/.claude/rules/` など）
- 執筆メモ: zk notebook の `writing` タグのノート。notebook の場所は `~/.config/zk/config.toml` の `[notebook] dir` で確かめる

## 表記をそろえる

校正のときは、次の表記もそろえる。

- 英数字や記号と日本語の間には、半角の空白を1つ入れる
- list の各項目の文末には「。」を付けない

## 提案の示し方

手順3では、変更をその場で反映しない。まず提案の list として示し、利用者の返事を待つ。

- 執筆メモは、ルールではなく、文章の目的に合わせて使う考え方である。そのページに当てはめるべきかは、ページごとに異なる
- そのため、執筆メモと執筆ルールに照らした変更は、意見の一つとして示す
- 変える必要がないと考えた項目も、その理由とともに示す

## コミットとビルド

- コミットは、1章（ドキュメントディレクトリの下の章のディレクトリ）の校正が終わったときにまとめて行う
- ビルドとテストは、校正中には行わず、すべての校正が終わったあとに行う

## 作業中の注意

### 利用者の手直し

利用者は、Emacs でファイルを直接直しながら校正を進める。

- ファイルは、触る前に読み直す。前に読んだときから変わっていることがある
- コミットの前に、Emacs のロックファイル（`.#ファイル名`）や自動保存ファイル（`#ファイル名#`）が残っていないかを確かめる。残っていれば、保存していない変更があるかもしれないので、利用者に確かめる

### 図の確認

mermaid の図を描き直すときは、反映する前に描いてみて、見え方を確かめる。

- リポジトリの `node_modules/.bin/mmdc` と、設定ファイル `build/mermaid.json` を使う
- 描いた画像は、作業用の一時ディレクトリに置く
- これは図1つの確認であり、校正の最後に行うビルドとは別のものとして扱う

HTML で書いた図（`figures/*.html`）を書く・直すときは、反映する前に `bin/figures` で PNG を作り、見え方を確かめる。

- 手順は、リポジトリの `README.md` の「HTML で書く図」に従う
- できた PNG は、HTML と一緒にコミットする
